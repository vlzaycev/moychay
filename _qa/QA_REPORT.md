## 5. Найденные проблемы

### Critical
Нет.

### High

**H1. Аналитика не подключена.**
- Причина: в `CONFIG` (`_build/build.py`) пустые GA4, Google Ads, Метрика и Pixel.
- Риск: при запуске рекламы не будет конверсий и данных для оптимизации, бюджет уйдёт вслепую.
- Исправление: получить ID, вписать, пересобрать. В Метрике завести цели `directions`, `whatsapp`, `telegram`. В Google Ads — конверсии с метками.

**H2. Медленный первый экран на мобильных (LCP 3,2–3,8 с, цель < 2,5 с).**
- Причина: CSS Google Fonts блокирует отрисовку (около 1,0–1,6 с). LCP-элемент — текст подзаголовка, он ждёт шрифты.
- Риск: дороже клик в Google Ads (Quality Score), больше отказов с мобильного трафика.
- Исправление: перенести шрифты на сайт (woff2, только нужные начертания и подмножества) с `font-display: swap` и `preload`. Либо подключать CSS Google Fonts асинхронно.

**H3. Лишний вес страницы на мобильных (около 3 МБ; по Lighthouse около 2 МБ лишнего).**
- Причина:
  - в двух слайд-шоу (8 + 7 фото) все изображения стоят в DOM и грузятся сразу;
  - на экранах с плотностью 2–3x браузер выбирает версии 1400w;
  - нет WebP / AVIF (около 0,8 МБ экономии).
- Риск: медленная загрузка и расход трафика на мобильном интернете.
- Исправление:
  - в слайд-шоу подгружать фото по очереди: текущее и следующее;
  - добавить промежуточный размер около 1000w;
  - сделать WebP-версии через `<picture>`.

### Medium

**M1. Нет security-заголовков:** HSTS, CSP, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy.
- Причина: GitHub Pages не даёт настраивать заголовки.
- Риск: кликджекинг (сайт можно встроить во фрейм), слабее защита при будущих изменениях.
- Исправление: Cloudflare → Rules → Transform Rules → Response Header, бесплатно. HSTS включать после недели стабильной работы https.

**M2. Короткий кэш статики:** картинки 4 часа, HTML 10 минут.
- Риск: повторные визиты грузят картинки заново.
- Исправление: Cloudflare Cache Rule для `/img/*`, срок в браузере 30 дней и больше. При замене фото менять имя файла.

**M3. Контраст основной кнопки.**
- Причина: белый текст 18px / 600 на `#B5602F`, соотношение около 4,0:1 при норме 4,5:1 (WCAG AA).
- Исправление: фон кнопки `#A4552A` (около 4,6:1). Визуально почти то же.

**M4. Зависимость от недокументированного CSV-экспорта Google Sheets.**
- Риск: Google может изменить поведение. Сейчас при сбое показывается запасной текст, это проверено тестами.
- Исправление: оставить как есть, smoke-тест `@live` следит за работой. Альтернатива на будущее — «Опубликовать в интернете» (`/pub?output=csv`).

**M5. Нет CI.**
- Риск: если поправить `index.html` руками в обход `build.py`, следующая сборка затрёт правку. Ошибки не ловятся автоматически.
- Исправление: GitHub Action на push, который запускает unit-тесты, без деплоя. Требует согласования.

## 6. Безопасность — что проверено и чисто
- Секретов и токенов в git нет; проверено регулярками по всем файлам.
- `.env` нет, переменных окружения нет.
- npm-зависимостей в production нет: тестовые лежат в `_qa/`, на сайт не публикуются.
- `.git`, `_build`, `_qa` на сайте отдают 404.
- **XSS:** данные из Google Таблицы выводятся через `textContent`, ссылки только `http(s)`; `javascript:` отбрасывается. Подтверждено тестом с вредоносной строкой.
- **CSRF:** на сайте нет форм и отправки данных — неприменимо.
- **CORS:** Google разрешает чтение таблицы с origin `teaphuket.com`. Сайт сам API не предоставляет.
- **SSL:** TLS 1.3, сертификат валиден (`CN=teaphuket.com`, Let's Encrypt, до 11.01.2027, автопродление Cloudflare).
- Все внешние ссылки с `target=_blank` имеют `rel=noopener`.

Таблица мероприятий открыта на чтение по ссылке. Это нужно для работы сайта. Не храните в ней ничего лишнего.

## 7. Деплой и откат
- **Деплой:** push в `main` → GitHub Pages собирает и публикует за 1–2 минуты. Через Cloudflare HTML кэшируется браузерами до 10 минут.
- **Откат:** в GitHub Desktop → History → правый клик по коммиту → Revert, затем Push origin. Или `git revert <sha>` и push. История коммитов полная.
- **Ошибки при деплое:** сайт статический, сборка Jekyll падает только при битом `_config.yml`, а его нет. Если `build.py` не запущен, это ловит unit-тест.

## 8. Что не удалось проверить и почему
- **Настоящий Safari и реальные устройства:** использован движок WebKit из Playwright. Он почти идентичен Safari, но это не реальный iPhone.
- **Полевые Core Web Vitals (INP / LCP из CrUX):** у нового сайта ещё нет данных. Появятся в PageSpeed Insights через несколько недель трафика.
- **Формы и валидация полей:** форм на сайте нет, проверять нечего.
- **Сканирование уязвимостей production:** не проводилось намеренно, по правилам аудита. Проверены только заголовки, TLS и публичные пути обычными GET-запросами.
- **Аналитика и конверсии:** ID не заданы, отправку событий проверить нельзя. Сама логика `track()` вызывается по `data-track`, это покрыто тестом ссылок.
